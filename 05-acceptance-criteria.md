# Tournament Management System — Product Document Pack

## 5. Acceptance Criteria

### A. Tournament creation

AC-1: Create tournament  
Given I am an admin, when I create a tournament with required basic information, then the tournament is saved as a draft.

AC-2: Required fields  
Given I am creating a tournament, when required fields are missing, then I cannot publish or start the tournament until those fields are completed.

AC-3: Format selection  
Given I am creating a tournament, when I select a tournament format, then the system shows the rules and required setup options for that format.

AC-4: Public/private visibility  
Given I am configuring visibility, when I choose private, then the tournament should not be publicly discoverable.

### B. Registration

AC-5: Open registration  
Given registration is enabled, when a participant visits the tournament page, then they can submit a registration request.

AC-6: Registration closed  
Given registration is closed, when a participant visits the tournament page, then they cannot register and must see the registration status.

AC-7: Custom fields  
Given the admin requires custom registration fields, when a participant registers, then the participant must complete those fields before registration is accepted.

AC-8: Registration limit  
Given the tournament has a participant limit, when the limit is reached, then new registrations are blocked or moved to a waitlist according to admin settings.

### C. Participant management

AC-9: Manual add  
Given I am an admin, when I add a participant by display name, then the participant appears in the participant list.

AC-10: Bulk add  
Given I am an admin, when I paste multiple participant names, then the system creates separate participant entries.

AC-11: Edit participant  
Given a participant has not been locked by tournament rules, when the admin edits the display name, then the updated name appears in the bracket and participant list.

AC-12: Substitute participant  
Given substitution is allowed, when the admin replaces a participant, then the new participant takes the correct bracket or group position.

AC-13: Remove participant before start  
Given the tournament has not started, when the admin removes a participant, then the bracket preview updates accordingly.

AC-14: Drop participant after start  
Given the tournament has started, when the admin marks a participant as dropped, then future matches reflect the drop according to tournament rules.

### D. Check-in

AC-15: Enable check-in  
Given check-in is enabled, when check-in opens, then registered participants can mark themselves as present.

AC-16: Checked-in list  
Given check-in is active, when the admin views participants, then checked-in and not-checked-in participants are clearly separated.

AC-17: Start with checked-in participants  
Given check-in is required, when the admin starts the tournament, then the admin must confirm how unchecked participants are handled.

### E. Seeding and bracket preview

AC-18: Manual seeding  
Given participants exist, when the admin changes seed order, then the bracket preview updates.

AC-19: Shuffle seeding  
Given participants exist, when the admin shuffles seeds, then participant order changes and the admin can review before starting.

AC-20: Final bracket lock  
Given the tournament has started, when the bracket is generated, then participants can distinguish final bracket matches from earlier previews.

### F. Tournament start

AC-21: Start tournament  
Given required setup is complete, when the admin starts the tournament, then active first-round matches are created.

AC-22: Prevent invalid start  
Given required setup is incomplete, when the admin attempts to start the tournament, then the system explains what must be fixed.

### G. Match operations

AC-23: Match page  
Given a match exists, when an admin, participant, or spectator views it, then they can see participants, score status, bracket position, and current state.

AC-24: Match state visibility  
Given match states change, when admins, participants, or spectators view the tournament, then they can see whether each match is pending, active, under review, completed, forfeited, or disputed.

AC-25: Match bracket position  
Given a match exists, when admins, participants, or spectators view the bracket or match page, then they can understand where the match sits in tournament progression.

AC-26: Upcoming match visibility  
Given a participant has a future match generated by the bracket, when they view the tournament, then they can see the opponent or pending source of that match.

### H. Score reporting

AC-27: Admin score reporting  
Given a match is ready for score reporting, when an admin enters a valid result, then the match is completed and the winner advances or standings update.

AC-28: Invalid score  
Given a score does not match the tournament scoring rules, when an admin or participant submits it, then the score is rejected with a clear explanation.

AC-29: Participant self-reporting  
Given self-reporting is enabled, when a participant submits a score, then the match is updated according to the confirmation or review rules.

AC-30: Match proof  
Given proof is required, when a score is submitted without proof, then the score cannot be finalized.

AC-31: Disputed score  
Given submitted scores conflict or are challenged, when a dispute is opened, then the match enters review status and does not advance until an admin resolves it.

AC-32: Forfeit  
Given a participant forfeits or no-shows, when the admin marks a forfeit, then the opponent advances or receives the configured result.

### I. Standings and tiebreakers

AC-33: Standings update  
Given a match result is submitted, when standings are displayed, then wins, losses, ties, points, and rank reflect the latest result.

AC-34: Tiebreakers  
Given participants are tied, when standings are calculated, then configured tiebreakers are applied in order.

AC-35: Tiebreaker visibility  
Given tiebreakers affect ranking, when admins, participants, or spectators view standings, then the tiebreaker values or explanation are visible.

### J. Two-stage tournaments

AC-36: Group creation  
Given a two-stage tournament is selected, when the admin creates groups, then each participant is assigned to one group.

AC-37: Automatic group assignment  
Given automatic group assignment is selected, when groups are generated, then participants are distributed across groups for admin review.

AC-38: Manual group assignment  
Given manual group assignment is selected, when the admin moves participants, then group membership updates before tournament start.

AC-39: Advancement rules  
Given group stage is complete, when advancement rules are applied, then the correct number of participants advances to the final stage.

AC-40: Final stage creation  
Given qualified participants are known, when the admin starts the final stage, then the final stage bracket is generated.

### K. Communication

AC-41: Announcements  
Given I am an admin, when I post an announcement, then it appears on the tournament page.

AC-42: Participant messages  
Given messaging is enabled, when admins send a tournament-related message, then selected participants receive it or can view it.

AC-43: Match updates  
Given a match status, participant, or score changes, when admins, participants, or spectators view the tournament, then the latest match information is shown.

### L. Completion and correction

AC-44: End tournament  
Given all required matches are complete, when the admin ends the tournament, then final results and placements are published.

AC-45: Prevent early completion  
Given required matches are incomplete, when the admin tries to end the tournament, then the system warns the admin and requires confirmation or completion.

AC-46: Edit result  
Given a score was entered incorrectly, when the admin edits the result, then bracket progression or standings update accordingly.

AC-47: Reopen tournament  
Given a tournament is completed, when the admin reopens it, then results can be corrected and republished.

AC-48: Correction visibility  
Given a completed result is changed, when admins, participants, or spectators view the tournament, then the updated result is visible.

### M. Sharing and viewing

AC-49: Public bracket viewing  
Given a tournament is public, when a spectator opens the tournament page, then they can view the bracket, standings, participants, and results.

AC-50: Printable bracket  
Given a bracket exists, when the admin selects print view, then a printer-friendly version is available.

AC-51: Shareable result  
Given a match or tournament result exists, when an admin, participant, or spectator shares it, then the shared view reflects the current result.

# MVP Recommendation

The first release should include:

1.  Tournament creation.
2.  Public/private tournament page.
3.  Single elimination, double elimination, round robin, and Swiss.
4.  Manual and bulk participant entry.
5.  Basic registration page.
6.  Manual and shuffled seeding.
7.  Bracket preview and start tournament.
8.  Admin score reporting.
9.  Standings and tiebreakers.
10. Final results publishing.

The second release should add:

1.  Check-in.
2.  Custom registration fields.
3.  Participant self-reporting.
4.  Match proof attachments.
5.  Two-stage tournaments.
6.  Substitutions, forfeits, and dispute handling.
7.  Tournament templates and correction/reopen workflows.
